# Volume — расчёт объёма объектов на конвейере

Модуль получает облако точек от конвейерного 3D-сканера и определяет объём
каждого объекта на ленте, а также координаты резов, делящих объект на порции
заданного объёма. Работает потоково: данные обрабатываются по мере
поступления, без хранения всего облака в памяти.

## Алгоритм

**Ленточная координата.** Лазер неподвижен, все срезы снимаются в одном месте.
Чтобы собрать из них деталь, из продольной координаты вычитается путь ленты:
`s = p·u − displacement`. В этой координате движущийся объект неподвижен,
и точки из разных кадров накапливаются в единой модели.

Каждая точка описывается тройкой: `s` — вдоль ленты, `w` — поперёк,
`h` — высота над лентой.

**Объём.** Ось `s` режется на слои толщиной `SLICE_STEP`, для каждого слоя по
его точкам считается площадь сечения, объём набегает суммой `V = Σ S_i · ds`.
Слой обсчитывается и выбрасывается из памяти, как только уезжает за камеры.

**Площадь сечения** считается одним из двух способов:

- *растровый* (`PROFILE_MODE = False`) — точки превращаются в бинарную
  картинку, дилатация замыкает контур, заливка заполняет внутренность,
  эрозия возвращает размер; держит вогнутости и отверстия. Нужен полный
  контур, то есть несколько камер;
- *профильный* (`PROFILE_MODE = True`) — площадь как интеграл под верхней
  огибающей силуэта. Достаточно одной камеры сверху, но предполагает
  сплошной материал под видимой поверхностью.

Низ сечения: `CLOSED_BOTTOM = True` пришивает контур к ленте (плоское дно),
`False` мостит щель хордой (шары, бочки).

**Сегментация.** Каждый объект занимает свой отрезок оси `s`. Если пустой
промежуток между группами точек длиннее `MIN_GAP`, объекты считаются разными.
Порог в миллиметрах ленты, от скорости не зависит.

**Точка реза.** При достижении `TARGET_VOLUME` координата реза находится
интерполяцией внутри слоя. Возвращаются два расстояния: от переднего края
детали (где резать) и от последнего кадра лазера (насколько запоздало
сообщение — поправка для контроллера ножа).

## Структура

```
Volume/
├── volume_core.py     ядро алгоритма
├── stream_api.py      потоковый интерфейс
├── data/              облака точек (*.pts) и картинки
├── models/            эталонные модели (*.stl)
└── tools/             вспомогательные программы
```

Все команды запускаются **из корня Volume** — инструменты в `tools/`
импортируют ядро из корня.

## Быстрый старт

```bash
python tools/axes_check.py data/scan.pts    # определить оси и уровень ленты
python tools/plot_pts.py data/scan.pts      # картинки: гистограмма, вид сбоку, срезы
python tools/run_pts.py data/scan.pts       # расчёт объёма
```

## Формат данных

Текстовый `.pts`, одна точка на строку, 4 или 3 числа:

```
кадр x y z        с индексом среза (предпочтительно)
x y z             без индекса — срезы восстанавливаются по координате
```

Ядро считает в миллиметрах. Если калибровка в сантиметрах — поставить
`UNIT_SCALE = 10.0` в `run_pts.py`.

## Файлы

### Корень

**`volume_core.py`** — ядро. Класс `ConveyorVolume`: вся математика объёма,
площади, сегментации и реза. Импортируется остальными, напрямую не
запускается.

```python
integ = ConveyorVolume(direction=[1, 0, 0], belt_level=0.0, slice_step=0.5)
integ.add_frame(points, displacement)
integ.finalize()
integ.volumes          # id -> объём
```

**`stream_api.py`** — потоковый интерфейс для установки реального времени.
Класс `VolumeStream`, метод `add_pts(pts, move)` вызывается на каждом кадре
и возвращает:

| Значение | Смысл |
|---|---|
| `None` | обычный кадр |
| `DetailParams(V, id)` | деталь проехала камеры целиком |
| `CutParams(V, id, len_from_start, len_from_frame)` | достигнут целевой объём |
| список | несколько событий за кадр |

В конце потока — `vs.finish()`.

### tools/

| Файл | Назначение |
|---|---|
| `run_pts.py` | основной расчёт объёма на файле |
| `plot_pts.py` | три картинки: гистограмма высот, вид сбоку, срезы |
| `axes_check.py` | определяет оси движения и высоты, уровень ленты |
| `profile_check.py` | текстовый профиль вдоль ленты: где детали, где мусор |
| `conveyor_volume.py` | тесты ядра на фигурах с известным объёмом |
| `virtual_experiment.py` | оценка точности: STL → облако с шумом → сравнение |
| `reference_cuts.py` | точный объём STL и эталонные резы равного объёма |
| `cut_stl.py` | разрезает STL плоскостью с плоской крышкой (для печати) |

```bash
python tools/run_pts.py data/scan.pts --info     # только диагностика
python tools/run_pts.py data/scan.pts --dump     # + точки после фильтров
python tools/profile_check.py data/scan.pts 10 x y
python tools/virtual_experiment.py models/fish.stl 4 z
python tools/reference_cuts.py models/fish.stl 4 z
python tools/cut_stl.py models/fish.stl --axis z --keep upper
```

## Параметры (CONFIG в run_pts.py)

| Параметр | Назначение |
|---|---|
| `UNIT_SCALE` | множитель координат при чтении (10.0 для сантиметров) |
| `DIRECTION`, `BELT_NORMAL` | оси движения и высоты |
| `BELT_LEVEL`, `BELT_EPS` | уровень ленты и запас среза над ним |
| `SLICE_STEP`, `CELL` | толщина слоя и разрешение сечения |
| `MIN_GAP` | минимальный зазор между деталями |
| `PROFILE_MODE`, `CLOSED_BOTTOM` | метод площади и обработка низа |
| `MIN_VOLUME` | фигуры мельче считаются мусором |
| `TARGET_VOLUME` | объём порции; `None` = резка отключена |
| `VOXEL`, `MIN_VOXEL_PTS` | фильтр шума по плотности |
| `MIN_BIN_FRAC` | фильтр редких слоёв |
| `W_MIN`, `W_MAX` | поперечные границы рабочей зоны |

## Настройка под новый скан

1. `axes_check.py` — печатает готовые строки `DIRECTION`, `BELT_NORMAL`,
   `BELT_LEVEL` для CONFIG. Если габариты в десять раз мельче ожидаемых,
   данные в сантиметрах: `UNIT_SCALE = 10.0`.
2. `profile_check.py` и `plot_pts.py` — посмотреть, где детали, где мусор
   и какой он высоты; по нему выбрать `BELT_EPS`.
3. `run_pts.py` — расчёт, дальше подбор параметров:

| Симптом | Решение |
|---|---|
| детали слиплись | уменьшить `MIN_GAP`, поднять `BELT_EPS` |
| деталь разбилась на части | увеличить `MIN_GAP` |
| объём завышен | проверить `PROFILE_MODE`, поднять `BELT_LEVEL` |
| объём занижен в разы | проверить порядок срезов (см. ниже) |
| после фильтров пусто | `MIN_VOXEL_PTS = 0`, `MIN_BIN_FRAC = 0` |
| мусор по краям ленты | задать `W_MIN`, `W_MAX` |

## Частые ошибки

**Объём занижен в сотни раз.** Срезы идут в обратном порядке: алгоритм ждёт,
что продольная координата убывает от кадра к кадру (так на реальной ленте),
а она растёт. Диагностика предупреждает и подсказывает поменять знак
`DIRECTION`.

**Объём отличается в 1000 раз.** Калибровка в сантиметрах, ядро считает в
миллиметрах: `UNIT_SCALE = 10.0`.

**После фильтров не осталось точек.** `MIN_VOXEL_PTS` подобран под плотное
облако и выкашивает разреженные детали, оставляя плотную ленту. Начать
с `MIN_VOXEL_PTS = 0` и включать фильтры по одному.

**Объём завышен на 10–15% при одной камере.** Профильный метод дозаливает
пустоту под скруглёнными боками. Если контур виден с двух сторон —
`PROFILE_MODE = False`.
