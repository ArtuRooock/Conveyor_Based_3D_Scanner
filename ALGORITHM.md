# Итеративный расчёт объёма предметов на конвейере по облаку точек

Считает объём предметов, движущихся по конвейерной ленте, по потоку кадров
3D-точек с лазерных триангуляционных сканеров. Несколько предметов в потоке
разделяются автоматически по зазору между ними; объём каждого выдаётся сразу
после того, как предмет полностью проехал зону обзора камер.

Зависимости: `numpy`, `scipy` (для визуализации — `matplotlib`).

Проверено на синтетических фигурах (коробка, полуцилиндр, шар, П-профиль
с пазом — ошибка 1–8 % при шуме точек 0.1 мм) и на реальном скане россыпи
из 14 мелких деталей (устойчивая сегментация, стабильные объёмы).

---

## 1. Постановка задачи

Дано:

- единичный вектор **u** — направление движения предметов по ленте;
- поток кадров: на каждый кадр — массив точек `(N, 3)` в общей мировой
  системе координат и `displacement` — путь, пройденный лентой к моменту
  кадра (показания энкодера или `скорость * время`);
- предметы лежат на плоской ленте; между предметами есть зазор.

Найти: объём каждого предмета, итеративно, по мере поступления кадров.

---

## 2. Порядок работы алгоритма

1. **Пиксели -> 3D-точки** (`LaserScanner`). На кадре камеры выделяется
   центр лазерной линии — пиксели `(u', v')`. Для каждого пикселя строится
   луч из оптического центра камеры:

   ```
   OP' = [u' - cx,  v' - cy,  f]
   ```

   Нормаль плоскости лазера получается поворотом вектора `[1, 0, 0]`
   вокруг оси Z на угол `eta` и вокруг оси Y на угол `theta`:

   ```
   N = Ry(theta) * Rz(eta) * [1, 0, 0]
   ```

   3D-точка — пересечение луча с плоскостью лазера, проходящей через точку
   `(b, 0, 0)`:

   ```
   P = (b * Nx / (N . OP')) * OP'
   ```

   Точки всех камер переводятся в общую мировую систему: `P_мир = R*P + t`.

2. **Кадр передаётся в `ConveyorVolume.add_frame(points, displacement)`**,
   где `displacement` — путь, пройденный лентой к моменту кадра.

3. **Переход в ленточную координату.** Для каждой точки вычисляется

   ```
   s_world = p . u                  (проекция на направление движения)
   s = s_world - displacement       (ленточная координата)
   ```

   В координате `s` движущийся предмет неподвижен, поэтому точки всех
   кадров одного предмета накапливаются в одном и том же месте оси `s`.
   Величина `s_world` дополнительно используется для оценки границы зоны
   обзора камер.

4. **Раскладка по слоям.** Ось `s` нарезана на слои толщиной `ds`;
   каждая точка попадает в свой слой в виде пары `(w, h)` —
   «поперёк ленты, высота над лентой».

5. **Разделение предметов.** Слои кадра группируются; пустой промежуток
   длиннее `min_gap` между группами означает границу между предметами.
   Каждая группа приписывается своему предмету, при необходимости
   заводится новый. Несколько предметов могут находиться в кадре
   одновременно.

6. **Закрытие слоёв.** Слой, уехавший за зону обзора камер, больше не
   пополнится: для него считается площадь сечения `S_i` (одним из двух
   методов, раздел 3.3), и объём предмета увеличивается: `V += S_i * ds`.
   Точки закрытого слоя удаляются из памяти, поэтому память не растёт
   с длиной потока.

7. **Завершение предмета.** Когда за зону камер уезжает весь предмет,
   вызывается callback `on_object` — по умолчанию печать
   `Figure N: V = ... mm^3` — и результат записывается в `volumes`,
   а положение предмета по ленте — в `ranges`.

---

## 3. Ключевые идеи

### 3.1. Ленточная координата

Для точки, «приклеенной» к ленте, `s = p.u - displacement` не меняется со
временем: рост `p.u` (предмет уезжает вперёд) компенсируется ростом
`displacement`. Точность напрямую зависит от точности `displacement` —
энкодер ленты предпочтительнее, чем `скорость * время`. Если облако точек
уже «развёрнуто» вдоль движения (координата содержит позицию среза),
достаточно `displacement = 0`.

### 3.2. Замыкание контура снизу

Камеры не видят низ предмета. Два режима (`closed_bottom`):

- **`True`** (коробки, профили, всё с плоским дном): контур принудительно
  пришивается к ленте. Допущение: пространство между видимой поверхностью
  и лентой заполнено материалом.
- **`False`** (шар, бочка на боку): контур строится только по реальным
  точкам; невидимая щель у точки касания мостится хордой между крайними
  нижними видимыми точками — минимальное замыкание без домысливания.

### 3.3. Площадь сечения

1. точки слоя наносятся на бинарную сетку с ячейкой `cell`;
2. одиночные точки-выбросы отбрасываются (по расстоянию до соседа);
3. дилатация склеивает разрывы контура; радиус подбирается адаптивно —
   наращивается, пока контур не сомкнётся (заливка начнёт заполнять
   внутренность) либо до потолка в долю размера сечения;
4. заливка внутренних дыр, затем эрозия на тот же радиус возвращает
   границу на место;
5. `S = число_пикселей * cell^2`. Вогнутости (пазы, выемки) сохраняются.

### 3.4. Разделение предметов

Каждый предмет занимает свой отрезок оси `s`; разрыв длиннее `min_gap`
(в единицах длины по ленте — порог не зависит от скорости) означает
границу. Требование: предметы не должны лежать вплотную или внахлёст.
Ограничение: разделение идёт только вдоль движения; два предмета бок о бок
на одном участке ленты посчитаются как один.

### 3.5. Допущение

Предмет считается сплошным: внутренние полости невидимы сканеру.

## 4. API (`volume_core.py`)

### `LaserScanner(f, cx, cy, b, eta, theta, R=None, t=None)`

Модель лазерного триангуляционного сканера (камера-обскура + плоскость
лазера). Параметры из калибровки: фокус `f` (пиксели), оптический центр
`cx, cy`, базис `b`, углы наклона плоскости лазера `eta` и оси лазера
`theta` (радианы). `R, t` — поворот и сдвиг из системы камеры в общую
мировую систему.

- `pixels_to_points(uv)` — переводит пиксели `(N, 2)` центра лазерной
  линии в 3D-точки `(N, 3)` мировой системы по формулам из раздела 2,
  шаг 1.

### `ConveyorVolume(direction, ...)`

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `direction` | — | единичный вектор движения предметов |
| `belt_normal` | `(0,0,1)` | нормаль плоскости ленты |
| `belt_level` | `0.0` | высота поверхности ленты в мировой системе |
| `slice_step` | `1.0` | толщина слоя `ds` |
| `close_margin` | `2` | запас открытых слоёв позади зоны камер |
| `closed_bottom` | `True` | `True`: плоское дно на ленте; `False`: шар и т.п. |
| `cell` | `0.25` | пиксель растра / ширина столбца огибающей |
| `min_gap` | `30.0` | минимальный зазор между предметами по ленте |
| `unit` | `"mm"` | подпись единиц в выводе |
| `on_object` | `None` | `callback(fig_id, volume)` при завершении предмета |
| `profile_mode` | `False` | `True`: одна камера сверху, площадь по огибающей |

Все размерные параметры — в тех же единицах, что и координаты точек.

- `add_frame(points, displacement)` — обработать кадр. Пустой массив тоже
  передавать (продвигает окно и завершает уехавшие предметы).
- `finalize()` — принудительно завершить активные предметы (конец потока);
  возвращает словарь `fig_id -> объём`.
- `volumes` — накопленные результаты, `fig_id -> объём`.
- `ranges` — положение предметов, `fig_id -> (s_min, s_max)`.

### Пример использования

```python
from volume_core import ConveyorVolume, LaserScanner

cams = [LaserScanner(f, cx, cy, b, eta, theta, R=Ri, t=ti)
        for (f, cx, cy, b, eta, theta, Ri, ti) in calib]

integ = ConveyorVolume(direction=[1, 0, 0], slice_step=1.0,
                       closed_bottom=True, min_gap=30.0)

while running:
    disp = read_encoder()
    pts = np.vstack([c.pixels_to_points(find_laser_line(grab(c)))
                     for c in cams])
    integ.add_frame(pts, disp)      # печатает "Figure N: V = ..." сам

integ.finalize()
```

## 5. Обработка файлов сканера (`run_pts.py`)

Раннер для офлайн-файлов формата `.pts` (`индекс_среза x y z` в строке).
Запуск: `python run_pts.py файл.pts` (`--info` — только диагностика,
`--dump` — сохранить отфильтрованные точки для визуальной проверки).

Диагностика перед расчётом показывает: диапазоны координат, развёрнуто ли
облако вдоль движения (нужно ли задавать `DISPLACEMENT_PER_FRAME`),
оценку уровня ленты по гистограмме высот.

Реальные сканы содержат мусор, поэтому перед ядром работают три фильтра
(настройки в блоке CONFIG):

1. **Фильтр шума по вокселям** (`VOXEL`, `MIN_VOXEL_PTS`): точки в
   разреженных вокселях — одиночные выбросы — отбрасываются.
2. **Фильтр ленты** (`BELT_LEVEL`, `BELT_EPS`): точки самой ленты
   отбрасываются, иначе они заполняют зазоры и предметы склеиваются.
   Уровень ленты берётся из CONFIG или оценивается автоматически;
   автооценку обязательно проверять визуализацией.
3. **Фильтр редких слоёв** (`MIN_BIN_FRAC`): слои вдоль ленты, где точек
   меньше заданной доли от медианного заполнения, считаются зазором —
   плотный мусор между предметами на порядки реже поверхности деталей.

Итог — живой вывод `Figure N: V = ...` плюс таблица: номер фигуры,
положение по `s` (для сопоставления с видом сбоку) и объём. Фигуры мельче
`MIN_VOLUME` отбрасываются.

Визуализация (`plot_pts.py`): `python plot_pts.py файл.pts` строит
гистограмму высот (искать полку ленты), вид сбоку и пять поперечных
срезов — по ним подбираются `BELT_LEVEL`, `closed_bottom`/`PROFILE_MODE`
и проверяется результат фильтров (в связке с `--dump`).

## 6. Точность и подбор параметров

Источники погрешности и что крутить:

- **`slice_step`** — у фигур с быстро меняющимся сечением толстый слой
  завышает объём. Уменьшать, пока в слое хватает точек.
- **`cell`** — квантование границы сечения; уменьшение повышает точность,
  пока плотность точек позволяет.
- **`belt_level`** — завышен: у предметов срезается низ; занижен:
  добавляется ложный «фундамент». Проверять по гистограмме высот и виду
  сбоку; периодически калибровать по пустой ленте.
- **`min_gap`** — больше минимального реального зазора между предметами,
  но меньше длины самого короткого предмета.
- **`displacement`** — ошибки пути ленты растягивают/сжимают предмет
  вдоль движения линейно в объём.
- **шум точек** — систематический шум расширяет контур примерно на свою
  величину; фильтры раннера убирают выбросы, но не смещение.
